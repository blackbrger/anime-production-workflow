# 动漫短片制作流程

把表演意图转成可制作、可检查的连续动作，再扩展到整片。生成、采用、技术正确、视觉通过和用户认可分别记录；文件多、帧率高、运镜平滑或软件测试成功都不能证明动画质量。

## 进入适当范围

先读取用户要求、现有作品与采用记录，确定当前属于：
- **新片制作**：按下述依赖推进；已有合格素材和设计直接复用。
- **已有镜头修订**：先定位缺陷，从最早失效的环节修到相邻接缝；不自动重做全片、角色设定或声音。
- **诊断或方案讨论**：检查证据并交付原因与方案；讨论不自动变成生成、改工程或换软件。

从现有信息提取片长、帧率、风格、角色与道具母版、声音决定、交付格式、当前最难动作和用户设置的确认点。仅询问会改变范围或方法的缺失信息，不重复问已有答案。用户要求保留的声音、片长、切点与角色设计是约束；有冲突时给出具体取舍，不悄悄更改。

阶段验收默认由制作端依据证据执行，不是每阶段请求用户批准。只有用户设定的确认点或实际缺失的必要决定需要等待；其他已授权且不依赖该决定的工作继续进行。

## 按依赖组织制作

| 阶段 | 应产出的依据 | 可以继续的条件 |
| --- | --- | --- |
| 故事与制作依据 | 用户目标、角色意图与变化、叙事节拍、镜头作用、空间关系、必要声音版本 | 关键行为有因果；画面与声音分工明确；依赖对白节奏的精修已确定采用的对白时长 |
| 表演与动态分镜 | 角色想做什么、注意谁、念头何时改变；粗画或低细节带时序预览，包含相邻镜头 | 不靠解说也能读懂关键行为；时长和剪辑支持动作。需要旁白传达的信息可保留，不要求所有内容静音自明 |
| 关键动作试制 | 用拟采用方法完成一个覆盖主要难点的短段；先粗动作，再验证必要的清稿与合成效果 | 在目标速度和观看尺寸下，轨迹、接触、造型与清晰度可接受；不能拿容易的眨眼代替手持物或遮挡难点 |
| 素材与关键姿势 | 稳定参考、必要分层/绑定/替换画，可信起止、接触、极限和收势姿势 | 相邻姿势说明得清中间运动；左右、握持、尺寸、遮挡和固定区域一致 |
| 过渡与曝光 | 根据动作分配每张画的曝光；低风险区间才采用适合的插值 | 运动间距、停留与清晰度共同成立；重要接触和轮廓重组没有靠混合图像蒙混 |
| 单镜头与接缝 | 固定机位检查，最终运镜检查，切点前后和修改区间两端对照 | 本轮修正没有损伤身份、未修改部位、相邻动作阶段、道具状态或视线 |
| 全片与交付 | 实际导出媒体、声音字幕、采用来源、约定的工程包和未解决项 | 全片节奏与视听事件成立；约定工程可重开且依赖齐备；技术、视觉与听感分别说明，必要未通过项不能标成最终完成 |

这是依赖关系，不要求全部串行。背景、低风险准备或原有声音可独立推进；影响主体动作的主要错误未解决时，不扩大依赖它的精细作画和批量镜头生产。用户明确要求粗样片时可以交付候选，标签不能代替质量判定。

短动作试制用于有真实不确定性的制作方法。已有同等难度、同等风格的通过样板可复用；低风险小修不必新增试片。样板长短由关键事件决定，不能把单个示例中的秒数、帧率或镜头数设为通用规定。

## 动作与素材的必要约束

- 用可观察的事件设计动作：起动、接触、遮挡、状态改变、分离、收势；只选本动作需要的事件。手握道具时明确肩肘腕连接、握点、道具方向及长度，物体转向造成的合理透视变化不能误判为漂移。
- 文本提示中的“保持完全一致”只是要求。生成结果须实际对齐比较；单张漂亮、身份相似不足以证明连续性。
- 根据可控性选择静态底图、运动部件、表情、道具、遮挡层或三维约束。不要强制所有镜头拆成同一套图层；已有整体生成片段确实合格时可以采用。
- 局部修订先检查 cel、贴图、图层或实例是否被其他帧共享；修改范围小于引用范围时，先隔离需要修改的实例，保护其他曝光位置。
- 用户明确要求区域外像素不变时，保留原底图并限定合成范围，比较源帧区域外像素；生成提示词不构成像素一致性保证，有损视频重编码也不能承诺解码像素逐点不变。
- 食物入口、物体转交等状态改变必须有可读的因果与遮挡。主动设计的剪辑省略可以成立，但应与前后镜头一致。
- 区分播放帧数、独立绘制张数、插值输出和曝光时长。时长正确并不证明间距合理；重复帧多也不自动表示失败。
- 停留应服务注意力或情绪。没有明确意图就不添加转头、眼神或眨眼填时间，也不强制所有停留都加呼吸。
- 删除或替换失真帧后，重新检查该段速度和区间边界。不能只保住总帧数；若运动缺口仍在，返回姿势或曝光设计。
- 来源分辨率应覆盖最终取景与推镜需求；低清小格图适合规划时，不自动成为可放大的成片原稿。

## 验收与方法切换

先按目标速度检查完整动作，再放大逐帧检查该镜头所有已识别的高风险区间，最后检查实际导出。缺陷记录使用“版本与位置—症状—原因假设—修法—同位置复查”，不要用自评分或完成数量代替证据。

上述完整动作检查适用于新动作、时序或运动结构变化。若同一基线已有相应验收，本轮只做不改变运动结构的微小像素修补，可复用原验收，集中复查修补区域、共享引用、时间邻接与实际交付；不无故重验整片。

只有确实看过的范围才能给视觉结论。仅有抽帧、曝光表或播放器运行状态时，明确连续播放观感仍有限；不得把“播放器到片尾”当作完整视觉审查。自动像素差和轨迹报警用于定位，不能自动认定合格。

同一主要缺陷经过连续两轮有针对性的修正仍没有可见改善时，执行方法复审：比较失败证据，改变至少一个实质因素，例如关键姿势、分层、轨迹约束、接触画法或镜头表达。两轮是默认复审点，可按用户预算与实际进展调整；不机械结束任务，也不只换提示词继续相同抽样。在既定范围内采用可行替代继续推进；涉及改变用户已锁定的画风、动作、片长或新增外部费用时，先完成可审阅的方案再处理必要决定。

新版本检查本轮修改范围、两端接缝、相邻镜头及风险相同的保留部分。保留部分可凭版本/像素一致性复用已有检查，但“没有改过”不等于“已经通过”。

音轨数据未变仅证明保留。动作事件时间改变时重新核对拟音或对白同步；旁白不能被误当成必须逐字对口型的角色对白。锁定音轨时优先调整允许的动作时序；无法同时满足的约束需明确提出。

## 工具与已有技能

使用当前可用工具，不假设某模型、收费 API 或 DCC 已连接。工程有 revision 防护时先读当前状态再写，保留上一稳定版本与候选来源。审阅不会自动触发重渲染；只有实际生成且检查过的文件才列为成果。

专项任务按需结合会话中已提供的技能，不必全部加载：
- 表演、重量、节奏：`animators-survival-kit`；造型和画风：`anime-visual-direction`。
- 二维游戏帧序列：`sprite-animation`；确实采用 Live2D 时再使用对应拆层与绑定技能。
- 采用 Blender 后再使用相应建模、角色、动画与渲染技能；当前栅格图制作按 `imagegen` 工作流。

本技能不自动建立 Project Conductor 项目、创建其他聊天或委派工作；大型项目组织由用户的实际请求决定。专项技能不可用时，按本技能的必要检查继续，不虚构工具执行。

交付先说观感结果及最严重的遗留，再给文件、验证和下一步。工作版以实际修改范围命名，避免以“完全流畅”命名未通过版本。
